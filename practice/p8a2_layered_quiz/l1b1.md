# Layer 1, batch 1: what things are

Answered in chat on 2026-11-16, copied here verbatim.

1. At temperature 0 versus 1, what changes in how the next token is chosen?

   **A:** temperature 0 means no random sampling, so greedy (highest probability) chosen.

2. In one tool call, what does the model do, and what does the harness do?

   **A:** not sure what you mean by "tool call" as it's very vague. I'm assuming you mean when the user prompts something the results in some tool being called as part of the harness producing a response. very briefly, one example non-error flow: user prompt -> harness adds global context which includes available tools for the model to call and and how to call them and sends the request to the model -> model response to harness in this example says "call tool xyz with params whatever" -> harness calls tool and gets response, sends it back to model -> model replies with next step which in this example is "tell the user: blah blah blah" (based on tool response) -> harness sends response to user without the extra instruction the model gave. (the user response is essentially a "tool call" of its own).

3. In a tool definition, what does the model use the **description** for, and what does it use the **input schema** for?

   **A:** description is what the tool should be used for, and is written with a model as the reader target (not a human). input schema are the parameters for the tool call, required and optional params are supported. and output schema is optional, and also supported (separate from input schema).

4. In one phrase each: what does RAG change, and what does fine-tuning change?

   **A:** RAG change? weird wording. RAG is a process/system. typically referring to vector embeddings of a corpus, to find relevant data to use to "augment" a prompt, later. fine tuning changes the model itself.
